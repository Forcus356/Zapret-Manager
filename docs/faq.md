# Частые вопросы

[К оглавлению](README.md) · [Обслуживание](operations.md)

## Это VPN или зарубежный прокси?

Это менеджер локальной схемы Dante + Zapret2. Выходной IP остаётся IP сервера. Публичный VPN-вход и клиенты настраиваются отдельно в Xray/3x-ui.

## Нужно ставить оба профиля?

Нет. Можно установить только YouTube или только Telegram. Они используют разные службы, пользователей, порты и очереди.

## Службы active, но YouTube всё ещё тормозит

Проверь по порядку:

1. Правильный ли инбаунд выбран в привязке Xray.
2. Доходит ли домен до маршрутизатора: клиент передаёт домен или включён подходящий sniffing.
3. Не перекрывает ли новое правило старое более широкое правило выше по списку.
4. Проходит ли `check --profile youtube` и что пишет DPI-журнал.
5. Воспроизводится ли длинное видео с устройства, а не только открывается страница YouTube.

Тест HTTPS-страницы не измеряет скорость видеопотока. На неё могут влиять стратегия DPI, канал VPS, CDN и регулирование выдачи конкретного формата. Менеджер не выполняет автоматический подбор стратегии для любого провайдера.

## Telegram частично работает, а часть DC недоступна

Посмотри `check --profile telegram`: результат каждого контрольного DC показан отдельно. `auto` проверяет два DC при настройке и не обещает доступность всех серверов. Порт 5222 тоже может быть закрыт у части DC. Не путай MTProto с обычным HTTPS; распознанный TLS/HTTP исключается из перевода порта.

## Почему звонки не заработали вместе с сообщениями?

UDP проходит без UDP-десинхронизации, а звонок может использовать произвольный P2P-адрес. Такой адрес не обязательно входит в Telegram geosite/geoip/CIDR. Нужна отдельная проверка с устройства и понимание конкретного маршрута.

## У меня уже есть ручной Zapret и Dante

Менеджер использует свои имена и не удаляет старую установку. Если 10808/200 заняты, выберет свободные значения. Старые Xray-правила при этом могут продолжать направлять трафик в прежний SOCKS — явно выбери новую привязку и проверь порядок. Удаляй старую схему отдельно после проверки новой.

## Xray находится в Docker

В bridge-контейнере `127.0.0.1` указывает на сам контейнер, а не на хост. Для текущей схемы нужен host networking или отдельно спроектированное сетевое подключение. Менеджер не публикует SOCKS на внешний интерфейс.

## Не работает горячее применение через API

Проверь HandlerService, RoutingService, адрес локального API, runtime JSON, путь к Xray и наличие geodata. У установленной версии ядра должны быть нужные API-команды. Не используй сгенерированный панелью runtime вместо её постоянного шаблона. Можно подготовить фрагменты через `xray show` и применить вручную в панели.

## Можно открыть SOCKS в интернет?

Профили используют loopback без клиентского пароля и предназначены для локального Xray. Публиковать их напрямую в интернете нельзя. Доступ к локальному административному API Xray также оставляй локальным.

## Как проверить, что IP остался российским?

`check` сравнивает прямой и проксированный публичный IP. Страна зависит от самого VPS и классификации адреса сервисом. Менеджер не ищет другой выход и не гарантирует геолокацию любого адреса у каждого сайта.

## Есть ARM, CentOS или Alpine?

Релиз 1.0.0 рассчитан на x86_64 Ubuntu/Debian с systemd и Python 3.10+. Другие архитектуры и дистрибутивы текущая предварительная проверка отвергает.

## Что приложить к сообщению об ошибке?

Версию менеджера, ОС, имя профиля, обезличенный вывод `status`, команду/пункт меню и фрагмент журнала вокруг ошибки. Убери UUID клиентов, токены, пароли, приватные ключи и ссылки подписок. Уязвимости сообщай по [политике безопасности](../SECURITY.ru_RU.md).
