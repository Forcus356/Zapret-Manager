# Tests / Тесты

[Главная](../README.ru_RU.md) · [Отчёт испытаний](../docs/testing.md)

## Unit-тесты

```bash
python3 -m unittest discover -s tests -v
```

Нужен Python 3.10+. Root, работающий Xray, PostgreSQL, Docker и сетевые загрузки не требуются: изменяющие системные команды подменяются тестовой средой, файлы создаются во временных каталогах.

`test_manager.py` содержит 45 тестов релиза 1.0.0: маршрутизация и порядок правил, независимость профилей, конфликты ресурсов, повторное применение, сохранение чужих изменений, откат ошибок, безопасность архивов и ограничения локального доступа.

## Сборка

Из корня репозитория:

```bash
python3 build_installer.py
bash -n install_forcus_zapret.sh
python3 build_release.py
```

Установщик генерируется из `forcus_zapret.py`. Не редактируй встроенную Python-копию в Bash-файле отдельно от исходника. Сборка выпускает ZIP, автономный установщик и SHA256SUMS в `dist/`.

## Интеграционные сценарии

| Файл | Назначение |
|---|---|
| `Dockerfile.systemd` | Отдельная среда Ubuntu 24.04 с systemd |
| `container_smoke.py` | Настоящие Dante/NFQUEUE/Xray, привязки SQLite/PostgreSQL/standalone, откаты и удаление |
| `container_prepare_reboot.py` | Подготовка профилей и тестовых данных к перезапуску контейнера |
| `container_after_reboot.py` | Проверка восстановления после перезапуска и очистка |

Это изменяющие конфигурацию сценарии для **отдельной одноразовой среды**, не обычные unit-тесты. Не запускай их на рабочем VPS и не монтируй в тестовый контейнер рабочие конфиги, БД или каталоги пользователей. Нужны systemd/NFQUEUE, необходимые привилегии контейнера, отдельный Xray с geodata и подготовленные тестовые данные. Скрипты отказываются работать без признаков контейнерной среды.

Порядок, версии компонентов и границы воспроизводимости описаны в [docs/testing.md](../docs/testing.md). Исходные сырые журналы испытаний и рабочие секреты в репозиторий не включены.

## GitHub Actions

[checks.yml](../.github/workflows/checks.yml) выполняет unit-тесты, проверку синтаксиса и воспроизводимости установщика, сборку и проверку контрольных сумм. Привилегированные интеграционные сценарии автоматически не запускаются. Локальный успешный прогон не подменяет результат GitHub Actions — его статус появится после публикации workflow.
