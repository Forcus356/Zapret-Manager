
- сохранение чужой параллельной правки runtime;
- защита незавершённой привязки при ошибке записи состояния;

## Границы проверки

- Перезапуск проверен у контейнера с настоящим systemd и восстановлением сетевого пространства. Физический VPS в ходе испытаний не перезагружался.
- Проверка установщика выполнена на Ubuntu 24.04; остальные заявленные современные Ubuntu/Debian используют совместимые компоненты, но отдельной матрицы реальных установок для каждого релиза ОС пока нет.
- Контрольный MTProto-запрос не входит в аккаунт, не проверяет переписку, авторизацию, все медиа-DC, звонки и произвольные P2P-соединения.
- Проверка YouTube через HTTPS не измеряет длительную передачу видеодорожки. Реальное видео и телефон проверяются отдельно на целевом провайдере.
- IPv4 проверен реальными соединениями. Правила/ACL IPv6 прошли разбор, но полный внешний IPv6-маршрут отдельным сквозным тестом не проверялся.
- Рабочие стратегии воспроизведены по предыдущей ручной установке на российском VPS, где пользователь подтвердил приемлемую скорость YouTube и работу Telegram. Новый менеджер в ходе разработки не заменял ту работающую установку.
- Полного универсального обхода любой блокировки любого Telegram DC эти проверки не доказывают. Режим `auto` сохраняет конкретные наблюдения о доступности портов.

## Воспроизведение интеграционных испытаний

Для разработки используй отдельную тестовую машину/контейнер. Systemd/NFQUEUE требуют привилегий контейнера; запускай только собственный собранный образ из `tests/Dockerfile.systemd` и не подключай к нему каталоги с рабочей конфигурацией VPS.

Порядок: установить оба профиля → предоставить тестовый Xray и публичные `geoip.dat`/`geosite.dat` в `/opt/test-xray` → при необходимости установить PostgreSQL только в тестовой среде → выполнить smoke → подготовку перезапуска → перезапуск контейнера → проверку после перезапуска. Сами скрипты отказываются работать без признаков контейнерной среды.
