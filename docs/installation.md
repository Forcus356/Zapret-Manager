# Установка

[К оглавлению](README.md) · [Xray / 3x-ui](xray/README.md) · [Обслуживание](operations.md)

## Требования

| Компонент | Требование |
|---|---|
| ОС | Ubuntu 22.04+ или Debian 12+ |
| Архитектура | x86_64 / amd64 |
| Python | 3.10+; системный Python не заменяется |
| Инициализация | Работающий systemd |
| Сеть | Доступ к apt-репозиториям и официальным релизам Zapret2 на GitHub |
| Ядро | nftables, NFQUEUE, conntrack; поддержка нужных модулей у хостера |
| Права | root / sudo для установки и управления |
| Для Xray | Уже установленное ядро, конфиг, geodata и локальное API для горячего применения |

Установка с настоящими службами проверена на Ubuntu 24.04. Остальные перечисленные ОС используют совместимые компоненты, но отдельной матрицы реальных установок для каждого выпуска пока нет. См. [границы проверки](testing.md).

## Интерактивная установка

```bash
curl -fsSL https://raw.githubusercontent.com/Forcus356/Zapret-Manager/main/install_forcus_zapret.sh -o /tmp/install_forcus_zapret.sh && sudo bash /tmp/install_forcus_zapret.sh
```

Если работаешь сразу от root, `sudo` можно убрать. На минимальной системе сначала установи `curl` через apt.

Мастер предлагает:

1. YouTube, Telegram или оба профиля.
2. Исходящий интерфейс: пустой ввод означает автоматическое определение.
3. Расширенную настройку портов и очередей; пустой ввод оставляет автоматический подбор.
4. Для Telegram — режим `auto`, `off` или `5222`.
5. Подтверждение установки зависимостей и служб.
6. Опциональную привязку к Xray с отдельным выбором инбаундов для каждого сервиса.

Меню после установки: `sudo forcus-zapret`. Оно не устанавливает профили без подтверждения.

## Установка через CLI

```bash
sudo bash /tmp/install_forcus_zapret.sh install --profile both --yes
```

Или отдельно, с явными значениями:

```bash
sudo bash /tmp/install_forcus_zapret.sh install \
  --profile youtube --port 10808 --queue 200 --interface ens3 --yes

sudo forcus-zapret install \
  --profile telegram --port 10809 --queue 201 --interface ens3 \
  --telegram-port-mode auto --yes
```

`ens3` — пример. Для автоматического определения не указывай `--interface`. Разным профилям нужны разные порты и очереди. Явно занятое значение вызывает отказ; без явного значения подбирается свободное. С `--profile both` параметры `--port` и `--queue` недопустимы.

Повторная установка не создаёт дубли и сохраняет существующие настройки профиля. Если установка второго профиля не удалась, первый может остаться установленным: посмотри `status` и журнал ошибки перед повторной попыткой.

## Что устанавливается

Системные зависимости через apt: `ca-certificates`, `curl`, `python3`, `python3-cryptography`, `iproute2`, `kmod`, `nftables`, `dante-server`.

Zapret2 загружается из официального release-архива. Начальная версия — **v1.0.7**, SHA256:

```text
547a5dce3f4820721a425680ea3f7f3971b7e9c772b8c795dd2d623148da0928
```

Для каждого профиля создаются отдельный пользователь, Dante-конфиг, две службы systemd и собственная таблица nftables. Существующий Dante не заменяется. Если пакет Dante устанавливается впервые и штатной конфигурации/службы до этого не было, его пустая штатная служба отключается: используются отдельные службы менеджера.

## Telegram port mode

| Режим | Действие |
|---|---|
| `auto` | Проверяет TCP/443 и TCP/5222 у двух контрольных DC; включает перевод, если 443 недоступен, а 5222 доступен хотя бы у одного |
| `off` | Оставляет исходные порты |
| `5222` | Принудительно включает перевод подходящего MTProto TCP/80 и TCP/443 на 5222 |

Перевод выполняется в Xray через `freedom redirect` и локальный SOCKS, с сохранением IP назначения. Сначала идут исключения для распознанного TLS/HTTP, затем перевод порта, затем обычные правила Telegram TCP/UDP. При использовании только Dante без привязки/экспорта Xray сам по себе этот выбор порт назначения не меняет.

Результат `auto` — наблюдение на момент установки, а не фоновый поиск и не универсальная гарантия. Доступность портов различается между DC и провайдерами. `check --profile telegram` показывает ответ каждого из пяти контрольных DC.

UDP проходит без UDP-десинхронизации. Медиа и звонки, особенно P2P, проверяются отдельно: произвольный IP собеседника не всегда определяется списком Telegram.

## Совместимость

- SOCKS доступен только на `127.0.0.1`. Для Xray в Docker здесь нужен host networking; loopback bridge-контейнера — другой адрес.
- Менеджер не создаёт публичный VPN-вход, сертификат или панель 3x-ui.
- Старые ручные установки с таблицами `zapret_dante` / `forcus_telegram` и службами `forcus-youtube-*` / `forcus-telegram-*` сохраняются. Новые профили используют другой префикс и обходят занятые ресурсы.
- Переключение Xray со старой ручной схемы на новую требует явной привязки и проверки порядка правил. Удаляй старую схему отдельно после проверки новой.
- Правила nftables учитывают IPv4 и IPv6; для внешнего IPv6 нужен действующий маршрут самого VPS. Сквозной IPv6-тест в отчёт релиза не входит.
- Общий firewall не очищается. Если NFQUEUE запрещён в виртуализации или ядре хостера, запуск менеджера сам по себе это ограничение не устранит.
